# Support

Ghostty Studio is an early preview. The latest release is the supported version; older preview
releases are not maintained as separate release lines.

## Start here

1. Confirm the Ghostty Studio and Ghostty versions shown in the app.
2. Reopen Ghostty after saving when the setting requires a reload or restart.
3. Check whether the app identifies another config layer or include as the effective source.
4. Review the exact diff and validation result rather than sharing the underlying file.
5. Try the latest release if you are using an older preview.

Use the [bug report](https://github.com/SteinsHead/ghostty-studio/issues/new?template=bug_report.yml)
for reproducible app behavior, the
[compatibility report](https://github.com/SteinsHead/ghostty-studio/issues/new?template=ghostty_compatibility.yml)
for a Ghostty version or setting contract, and the
[feature request](https://github.com/SteinsHead/ghostty-studio/issues/new?template=feature_request.yml)
for a workflow that is not supported yet.

Ghostty itself is maintained separately. If the same behavior occurs without Ghostty Studio and does
not depend on a Studio-generated change, check the
[Ghostty project](https://github.com/ghostty-org/ghostty) before filing here.

## Share safely

Never upload a complete Ghostty configuration, unredacted logs, or real background images. Remove
usernames, private paths, hostnames, commands, environment values, tokens, repository names, and
terminal content from text and media. Prefer a minimal synthetic fragment and describe the config
topology without revealing paths.

For a vulnerability or accidental exposure risk, stop and use
[GitHub private vulnerability reporting](https://github.com/SteinsHead/ghostty-studio/security/advisories/new).
Do not open a public issue.
